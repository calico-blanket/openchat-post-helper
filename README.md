# openchat-post-helper（オープンチャット投稿ヘルパー）

Slack・X・LINE公式・note・議員の活動告知・チラシ画像を、LINE オープンチャットへ投稿しやすい形（コピー用の文章）に整える PWA です。

- オープンチャットには自動投稿できないため、アプリは**コピー用の文章を作るところまで**です。投稿は人が手で貼ります。
- 個人で使うほか、フォークして別のチーム・グループでも使えるようにしています（[フォークして使う手順](#フォークして使う手順)）。

## できること

| 入力 | 動き |
|---|---|
| 共有シート（URL・本文） | Android の共有メニューから開くと、自動で「文章を整える」まで進みます |
| 自由入力 | 本文の貼り付け（URL は任意） |
| 画像 | 「画像を選ぶ」でチラシなどを選ぶと、AI が文字と日時を読み取ります（共有シートからの画像受け取りは未対応） |

- **URL からの本文取得:** note は記事 API、X は oEmbed（長い投稿で途中までしか取れないときは、外部の fxtwitter から全文を取り直します）、そのほかのページは HTML から本文らしき部分を取ります。Slack・Instagram・Threads の URL からはログインが必要で取れないので、本文の貼り付けを促します。
- **URL を整える:** 外部の短縮サービスは使わず、`utm_…` などの追跡用パラメーターや共有ボタンが付ける部分（note の `sub_rt`、X の `s`・`t`、Instagram の `igsh` など）を取り除きます。Amazon の商品ページは `/dp/商品番号` の公式の短い形にします。行き先は変わりません。
- **AI（Gemini）が作るもの:** タイトル、概略（「・」の箇条書き。体言止め中心）、種別（スケジュール／記事／議員活動）、開催日時・場所・申込締切・出演者、画像からの文字の読み取り。
- **AI（Gemini・Jev）の使い分けと費用:** 下の「[AI・Jev・GAS の使いどころと費用](#aijevgas-の使いどころと費用)」にまとめています。
- **AI に任せないもの:**
  - 曜日は、日付からコードで計算します。
  - 「本日」「明日」は、コピーする時点で付けます。
  - 出典行（「Slackからの転載です。」など）と定型句は、ひな形から自動で付けます。
  - 議員名タグは、議員名一覧との文字列一致で付けます。
  - 日時が「AまたはB」「未定」のように確定していない場合は、日時を言い切らずに空にして警告します（AI の判定に加え、原文の表現をコードでも確かめます）。
- **出力（コピー用）:**
  1. **トーク本体:** 読んだ人が最初の画面で「いつ・どこで会えるか」をつかめる形にします。
     - スケジュール型: 【タイトル】＋📅日時＋📍場所（「対面＆オンライン」のような短い表記。テレビ番組への出演・放送なら「テレビ」）＋🎤出演者＋⏰申込締切＋📝要申し込み（URL つき。URL は手で消して「要申し込み」だけにもできます）＋出典行＋結び。イベントの概要はトークに載せず、スレッドの原文で読んでもらいます。
     - 参加 URL（配信・オンライン会議）と申込 URL（申込フォーム）は、AI が本文から見つけます。AI が示した URL が原文に実際にあるかをコードで確かめ、無いものは外します。Zoom などの会議 URL には「公開してよいか」の警告を出します。
     - トーク本体は、AI の提案文をそのまま編集できます。手で直した文は、そのまま保存されます。
     - 記事型・議員活動型: 【タイトル】＋概略（箇条書き）＋出典行＋「詳細はスレッドにて ➡️」
  2. **スレッド（使うかどうかを選べます）:** 前置き＋**原文そのまま**（AI を通しません）。長文は段落の切れ目で分け、1通ずつコピーできます。X・Instagram・Threads は「URL だけの1通」を別にコピーできます。メモ欄の内容をコメントとして添えられます。
     - スレッドを使うとき、トーク本体の最後は「詳細はスレッドにて ➡️」です。
     - スレッドを使わないとき、トーク本体の最後は「全文はこちら ⬇️」と URL になり、トークだけで完結します（元の URL が YouTube のときは、本文ではなく動画なので「動画はこちら ⬇️」。文言は `Config.gs` の `talk.linkLine`・`talk.videoLinkLine`。URL が無ければ結びの行は出ません）。
     - 初期値は、ログインなしで読める note・一般の Web 記事が「使わない」、ログインが必要な X・Instagram・Threads・Slack・LINE などが「使う」です。URL が無いときは常に「使う」です。
- **要約ボタン:** ②の「長いときは要約する」にあります。押したときだけ AI を呼びます。結果は編集できる下書きになり、「原文に戻す」で戻せます。原文の URL・日付・時刻・数字が要約から消えた場合と、原文にないものが要約に現れた場合は、コードで検出して警告します。
- **保存・一覧:** スプレッドシートに 1 行 1 件で保存し、一覧・検索（カテゴリ横断）・編集・削除ができます。発信者・トーク本文（手で直した文）・参加 URL・申込 URL も記録します。一覧から開くと、保存したトーク本文がそのまま戻ります。同じ URL を保存しようとすると警告します。
  - 編集は、基本はアプリで行ってください（日付の形式・種別の表記・タグの区切り・数式インジェクション対策が自動でそろいます）。誤字の修正などはスプレッドシートで直接直しても構いませんが、「開催日時（ISO）」「種別」「タグ」は形式どおりに書いてください。

## 使い方

1. **入力:** 共有メニューから開くか、「新規」で本文・URL・画像を入れて「文章を整える」を押します。
2. **① トークに貼る:** AI の提案文が入った欄を確かめ、必要なら削ったり書き足したりしてから、「トーク本体をコピー」を押してオープンチャットのトークに貼ります。
3. **② スレッドに貼る:** ①で貼った投稿のスレッドに、「1通目をコピー」から順に貼ります。トーク本体だけで済ませたいときは「スレッドにも投稿する」のチェックを外します。原文は全文のまま貼ります（前置きは「↑○○さんの投稿です。」のような1種類）。長すぎるときは、同じ場所の「長いときは要約する」で AI に縮めてもらえます（前置きが「↑○○さんの投稿の要約です。」に変わります）。不要な行は「スレッドの内容を直す」の原文から消せます。Slack からコピーした文に絵文字の名前（`:sparkles:` や `:ピカピカ:` など）が残っているときは、「絵文字の名前を取り除く」ボタンが出ます。押すと名前と末尾の「（編集済み）」を取り除き、行の最後だった所には「。」を付けます（句読点や閉じかっこで終わる行には付けません。「取り除く前に戻す」で元に戻せます）。
4. **③ 記録する（任意）:** 発信者・タイトル・日時などの記録用の項目を確かめ、カテゴリを選んで「保存する」を押すと、スプレッドシートに残り、あとで一覧から探せます。

発信者は、③の「発信者」の下にある候補ボタン（「名前なし」「運営アカウント」など）で切り替えられます。発信者は常に記録に残ります。Slack の場合、名前を選ぶとスレッドの前置きの後ろに「発信者は運営アカウントです。」が付き、「名前なし」なら付きません（全文・抜粋の書き分けは②の選択だけで決まります）。候補は設定画面で追加・削除・並べ替えできます。

### 入力元ごとの入れ方（実機で確かめた結果）

| 入力元 | 入れ方 |
|---|---|
| X | 共有メニューか URL の入力で本文を取ります。**長い投稿は約250字で切れます**（警告が出ます）。X で「さらに表示」を開いて全文をコピーし、本文欄に貼ってから、もう一度「文章を整える」を押してください |
| Slack | 他のアプリへの共有や URL では取れません。本文をコピーして本文欄に貼ります。スマホの共有では長い URL が「drive.google.com/…」と省略されるので（復元はできません）、URL を全部入れたいときは PC の Slack でコピーします。省略された URL があるメッセージは、「○通目をコピー」を押したときに確認が出ます |
| LINE 公式 | スマホは共有メニューからアプリに送れます。PC は本文をコピーして本文欄に貼ります |
| note・一般の Web 記事 | 共有メニューか URL の入力で本文を取ります |
| Instagram・Threads | URL では本文を取れません。本文をコピーして本文欄に貼ります（URL も入れるとスレッドの1通目になります） |

本文欄に貼った文と URL から取った文の両方があるときは、長いほうを原文に使います。

①の文を手で直す前は、③の項目（発信者・タイトル・日時など）を変えると、①の文も自動で作り直されます。手で直したあとは上書きしません。③の内容で作り直したいときは「③の項目から作り直す」を押します（手で直した文は消えるので、確認が出ます）。前置き・原文・要約・コメントは、②の「スレッドの内容を直す」を開いて直します。

## AI・Jev・GAS の使いどころと費用

### どの操作で何を使うか

| 操作 | AI（Gemini） | Jev | GAS | 費用 |
|---|---|---|---|---|
| 「文章を整える」 | 1回呼ぶ | 1回呼ぶ（キーを設定したときだけ） | 本文の取得・AI の呼び出し・結果の検証 | **かかる** |
| 「要約する」（結果画面の②） | 1回呼ぶ | 使わない | AI の呼び出し | **かかる** |
| 「AI を使わずに手で作る」 | 使わない | 使わない | 使わない | なし |
| コピー・投稿文の組み立て・分割 | 使わない | 使わない | 使わない（画面の中だけで処理） | なし |
| 保存・一覧・検索・編集・削除 | 使わない | 使わない | スプレッドシートの読み書き（公開用スプレッドシートの書き直しも） | なし |
| 記録の一覧ページを見る | 使わない | 使わない | スプレッドシートを読むだけ | なし |
| 設定（カテゴリ・タグ・発信者の候補） | 使わない | 使わない | スクリプトプロパティの読み書き | なし |

本文も画像もないとき（例: Slack の URL だけ）は、「文章を整える」を押しても AI は呼ばず、本文の貼り付けを促すだけです。

### Gemini と Jev の使い分け

| | Gemini（文章を読んで作る AI） | Jev（判定に特化した AI） |
|---|---|---|
| 役割 | 本文や画像を読んで、文章や項目を**作る** | 決まった選択肢から**選ぶ**・当てはまるかを**判定する** |
| 担当 | タイトル、概略（要点）、開催日・時刻・申込締切・出演者、開催形式と地名、参加 URL・申込 URL、画像の文字の読み取り、要約 | 種別（3つから選ぶ）、カテゴリ（登録済みから選ぶ）、タグ（1つずつ「当てはまる確率」を出し、0.5 以上を付ける） |
| 種別・カテゴリ・タグ | 毎回いっしょに判定し、**Jev が失敗したときの予備**にする | キーがあれば、こちらの判定を優先する |
| 無いとき | 必須（キーが無いと「文章を整える」は使えない） | 任意。キーが無ければ Gemini がまとめて判定する |

- **Jev を使う利点:** タグの数が増えても1つずつ確率で判定するので、当てはまるタグを取りこぼしにくくなります。費用も Gemini より安く済みます。
- 2つは同時に（並列で）呼ぶので、Jev を使っても待ち時間はほとんど増えません。
- Jev が失敗しても（キーの誤りなど）、Gemini の判定で続けられます。原因は GAS エディタで `testJev` を実行すると確かめられます。

**AI を使わず、コードで処理しているもの**（AI の誤りが入らないようにするため）

- スレッドの原文（一字も変えずにそのまま使う）
- 曜日・「本日」「明日」の計算
- 出典行・前置き・定型句（ひな形から作る）、場所の表記（「対面＆オンライン」）の組み立て
- 長文の分割、要約から消えた URL・日付・数字などの検出
- AI が返した値の検証（日付が実在するか、未確定の日時を空にする、URL が原文にあるか、タイトルの【】の二重防止、概略の箇条書きへの整形）
- URL を整える（追跡用パラメーターの除去、Amazon の短い形）、議員名タグ（名前の一致）、重複 URL の警告

### GAS の使われどころ

GAS は、画面（PWA）とスプレッドシート・外部サービスの間に立つ「裏方」です。

- **すべての操作の入口（API）:** 画面からの依頼を受け、合言葉を照合してから処理します。
- **本文の取得:** note の記事、X の oEmbed、一般の Web ページから本文を取ってきます。
- **AI の呼び出し:** Gemini と Jev を呼びます。**API キーは GAS のスクリプトプロパティにだけ置き**、画面やリポジトリには出しません。
- **保存先（スプレッドシート）の読み書き:** 1行1件で保存し、一覧・検索・編集・削除をします。
- **設定の保存:** カテゴリ・タグ・発信者の候補を、スクリプトプロパティに保存します。
- **記録の一覧ページの入口:** 合言葉なしで、公開してよい項目だけを返します（`ARCHIVE_PUBLIC` が `true` のときだけ）。

GAS は無料です。ただし Google アカウントごとに1日あたりの上限があり、**同じアカウントで動かしている、ほかの GAS とも合算されます**。

| 項目 | 上限（無料のアカウント） | このアプリの使用量の目安 |
|---|---|---|
| 外部への通信（Gemini・Jev・本文の取得） | 1日 20,000 回 | 「文章を整える」1回で 5 回前後 |
| スクリプトプロパティの読み書き | 1日 50,000 回 | 1回の操作で十数回 |
| 1回の実行時間 | 6 分 | 「文章を整える」で数秒 |

1日に数十件を整える程度なら、上限の 1〜2% 程度です。

### 費用の目安

2026年10月時点の公式の料金をもとにした目安です（1ドル＝150円で換算）。実際の費用は、Google AI Studio と TypeSafe の管理画面で確かめてください。

**サービスごと**

| サービス | 料金 | 注意 |
|---|---|---|
| Gemini API（gemini-3.1-flash-lite） | 有料枠: 入力 100万トークンあたり 0.25 ドル、出力 100万トークンあたり 1.50 ドル | 無料枠もあるが、**送った内容が Google の製品改善に使われる**。回数の上限も低い |
| Jev（TypeSafe） | 入力 100万トークンあたり 0.042 ドル（出力は無料） | 任意 |
| GAS・Google スプレッドシート | 無料 | 1日あたりの上限あり（上の表） |
| Vercel（Hobby プラン） | 無料 | 利用条件は「個人・非営利の利用に限る」。団体での使い方が当てはまるかは各自で確かめる。画面は静的ファイルだけなので、Cloudflare Pages などほかの無料の置き場所にも移せる |
| GitHub | 無料 | 非公開リポジトリも無料 |
| note の記事 API・X の oEmbed | 無料 | 公式に保証された使い方ではないため、仕様が変わると本文を取れなくなる可能性がある（その場合は貼り付けで続けられる） |
| fxtwitter（api.fxtwitter.com。X の長い投稿の全文用） | 無料 | 外部の非公式サービス。oEmbed が途中で切れたときだけ、公開されている投稿の URL（ユーザー名と ID）を送る。止まっても、貼り付けで続けられる |

**1回あたり（有料枠の場合）**

| 操作 | トークンの目安 | 費用の目安 |
|---|---|---|
| 短い本文（Slack など 〜1,000字）で「文章を整える」 | 入力 約2,500、出力 約1,000 | 約 0.3 円 |
| note の長文（〜8,500字）で「文章を整える」 | 入力 約10,000、出力 約1,000 | 約 0.6 円 |
| チラシ画像を1枚付ける | 入力が約1,500 増える | ＋約 0.06 円 |
| 「要約する」（〜12,000字） | 入力 約13,000、出力 約1,000 | 約 0.7 円 |
| Jev（「文章を整える」1回ごと） | 入力 数百〜数十万（本文の長さ × 質問の数〔種別・カテゴリ・タグの数〕で変わる） | 0.01 円未満〜約 2 円 |

- 日本語は1文字が約1トークンとして見積もっています。出力には AI の内部の考える過程の分が含まれることがあるので、多めに見積もっています。
- **1か月の目安:** 1日30件を整え（うち要約3件）、Jev も使う場合で、**月に数百円〜千円程度**です。
- 予期しない使いすぎに備えて、必ず月額の上限を設定してください（下の「料金の上限と予算アラート」）。

### アプリで概算を確かめる

- **今回の概算:** 「文章を整える」のあと、結果画面の上に「処理時間 ○秒／今回の AI の概算 約 0.3 円」と出ます。「要約する」のあとは、読み上げと状態の表示に概算が出ます。
- **今月の概算:** 設定画面の「AI の使用量（概算）」に「2026年10月の概算: 約 ○○ 円（文章を整える ○回・要約 ○回）」と出ます。
- **1回ごとの記録:** 保存先スプレッドシートの「利用量」シートに、日時・操作・モデル・トークン数・概算（円）が1行ずつ残ります。月ごとの集計や、どの操作が多いかの確認に使えます。

概算は、Gemini と Jev が応答の中で返す「使ったトークン数」に、`gas/Config.gs` の `pricing`（料金表。1ドル＝150円）を掛けたものです。**無料枠で使っている場合、実際の請求は 0 円**です。料金改定・為替・モデルの変更があったら `pricing` を書き換えてください。正確な請求額は、各サービスの管理画面で確かめます。

| サービス | 実際の請求額を確かめる場所 |
|---|---|
| Gemini | Google AI Studio の「Spend」（支出）ページ、または Google Cloud コンソールの「お支払い」→「レポート」 |
| Jev | TypeSafe の管理画面（https://console.typesafe.ai） |
| Vercel | ダッシュボードの「Usage」（無料の範囲内かどうか） |

## フォークして使う手順

所要時間の目安は 30〜60 分です。

### 1. リポジトリをフォークし、設定を書き換える

`gas/Config.gs` を開き、次を自分たち用に直します。

- `teamName`（チーム名）
- `defaultCategories`（初期カテゴリ。初回起動時に1度だけ登録され、以後は画面から増減できる）
- `defaultAuthors`（発信者の名前の候補。初回起動時に1度だけ登録され、以後は設定画面から増減できる）
- `legislators`（議員名一覧。本文などに含まれていればタグとして付く）
- `sourceLines` `threadPrefixes` `talk` `commentLine`（出典行・前置き・定型句のひな形。`threadPrefixes` は `full`（全文）と `summary`（要約版）の2組に分かれる。古い形の1組だけの設定や、`summary` が1文だけの設定も使える）
- `placeLabels`（トークの場所の表記。`{area}` に地名が入る。例: `対面（{area}）＆オンライン`。`tv` はテレビ出演の表記）
- `threadDefaults`（入力元ごとの「スレッドにも投稿する」の初期値）、`urlFirstSources`（スレッドの1通目を URL だけにする入力元）、`talk.linkLine`（スレッドを使わないときの結び）
- `limits.llmInputMaxCharsBySource`（入力元ごとの AI に渡す文字数の上限。note は 20,000 文字）
- `pricing`（使用量の概算に使う料金表と為替。料金改定のときに書き換える）
- `publicSheet`（公開用スプレッドシートの「記録一覧」タブの名前・タイトルのリンク先の URL・載せる列と並び）
- `limits`（文字数の上限。実機確認の結果で調整）

アイコンは仮のものです。`icons/icon-192.png` と `icons/icon-512.png` を差し替えてください（`scripts/generate_icons.js` を書き換えて `npm run icons` でも作れます）。アプリ名は `manifest.json` と `index.html` の `<title>` にあります。

### 2. スプレッドシートと GAS を用意する

1. Google ドライブで新しいスプレッドシートを作る（名前は自由）。
2. メニューの「拡張機能」→「Apps Script」を開く。
3. 左の「プロジェクトの設定」（歯車）で「『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにする。
4. エディタに次の 3 ファイルを作り、リポジトリの内容をそれぞれ貼り付けて保存する。
   - `Code.gs` ← `gas/Code.gs`
   - `Config.gs` ← `gas/Config.gs`（「＋」→「スクリプト」で追加し、名前を `Config` にする）
   - `appsscript.json` ← `gas/appsscript.json`

> **注意:** GAS は GitHub と自動では同期しません。リポジトリの `gas/` を変えたら、毎回エディタに貼り付け直して、デプロイを更新してください（下の「GAS を更新したとき」）。

### 3. API キーと合言葉をスクリプトプロパティに入れる

「プロジェクトの設定」→「スクリプト プロパティ」に追加します。**キーや合言葉を、コードやリポジトリには書かないでください。**

| プロパティ | 必須 | 内容 |
|---|---|---|
| `SHARED_TOKEN` | 必須 | 合言葉。**未設定だと API はすべて拒否されます。** 推測されにくい長い文字列にする（例: パスワード管理ソフトで 32 文字以上を生成） |
| `GEMINI_API_KEY` | 必須 | [Google AI Studio](https://aistudio.google.com/) で作った API キー |
| `GEMINI_MODEL` | 任意 | モデル名。省略時は `gemini-3.1-flash-lite`（Google の告知では 2027-05-07 に提供終了予定。移行先は `gemini-3.5-flash-lite`）。2.5 系は使わないでください |
| `TYPESAFE_API_KEY` | 任意 | Jev（TypeSafe）の API キー。設定すると、種別・カテゴリ・タグを Jev が判定し、Gemini と並列に呼びます。未設定なら Gemini がまとめて判定します |
| `PUBLIC_SPREADSHEET_ID` | 任意 | 公開用スプレッドシートの ID。GAS エディタで `createPublicSpreadsheet` を実行すると自動で入ります（下の「公開用スプレッドシート」） |
| `ARCHIVE_PUBLIC` | 任意 | `true` にすると、記録の一覧ページ（`archive.html`）用の読み取り専用の入口が動きます。未設定・`true` 以外なら公開しません（下の「記録の一覧ページ」） |
| `ANTHROPIC_API_KEY` | 任意 | Claude（Anthropic）の API キー。Gemini が混み合い・上限のままのとき（HTTP 429・500・503・504）だけ、Claude Haiku に切り替えます（下の「Gemini が使えないときの予備（Claude）」）。**Claude の API は無料枠がありません**（未設定なら切り替えません） |
| `CLAUDE_MODEL` | 任意 | 予備の Claude のモデル名。省略時は `claude-haiku-5-5` |
| `YOUTUBE_API_KEY` | 任意 | YouTube Data API のキー。設定すると、YouTube の URL から動画の公開日を「発信日」に自動で入れます。未設定なら YouTube の発信日は手で入れます（下の「発信日の自動入力」） |

### 4. 権限を承認する

エディタ上部の関数の選択で `authorizeOnce` を選び、「実行」を押して、表示される権限（スプレッドシート・外部通信）を承認します。
Web アプリ経由では承認画面が出ないため、この手順を飛ばすと保存や通信が失敗します。

### 5. Web アプリとしてデプロイする

1. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」。
2. 「次のユーザーとして実行」: 自分。「アクセスできるユーザー」: 全員。
3. 表示された URL（`https://script.google.com/macros/s/…/exec`）を控える。

「全員」に公開しますが、合言葉が一致しない呼び出しはすべて拒否されます。

### 6. PWA を Vercel に公開する

1. [Vercel](https://vercel.com/) で「Add New… → Project」からフォークしたリポジトリを選ぶ。
2. Framework Preset は「Other」、ビルドコマンドは空のままでデプロイする（静的ファイルだけです）。
3. `.vercelignore` で、テスト・GAS のコード・ドキュメントは公開しないようにしています。

### 7. スマホに入れて設定する

1. Android の Chrome で Vercel の URL を開き、メニューの「ホーム画面に追加」（または「アプリをインストール」）を選ぶ。
2. アプリを開き、設定画面に GAS の URL と合言葉を入れて「保存して接続を確かめる」を押す。
3. 他のアプリの「共有」メニューに「投稿ヘルパー」が出れば完了です。

### 8. 実機で確認する

[docs/verification-checklist.md](docs/verification-checklist.md) に、確認の状況（確認済み・確認不要・使いながら）と手順をまとめています。全部を一度に試す必要はありません。共有で本文が入るか・記録の一覧ページが開けるかを確かめれば、あとは使いながらで大丈夫です。

### 発信日の自動入力

記録には「発信日」（元の投稿・動画が出た日）の欄があります。「文章を整える」を押したとき、元の URL から次のように自動で入ります。入らなかったときは、結果画面の「発信日」欄に手で入れられます（空でも保存できます）。

- **X・Instagram・Threads・Slack:** URL の中の番号から日付を計算します。外部サービスも設定も要りません。
- **YouTube:** YouTube Data API で公開日を調べます。`YOUTUBE_API_KEY` が必要です。
- **note・LINE公式・チラシなど:** 自動では入りません（手で入れます）。

### YouTube の URL からの本文の読み取り

`YOUTUBE_API_KEY` を設定してあると、YouTube の URL を入れて「文章を整える」を押したとき、同じ API の1回の呼び出しで、公開日に加えて動画の**タイトル・説明欄（概要欄）・チャンネル名**も取ります（追加の呼び出し・追加の費用はありません）。YouTube のページを直接取りに行く方法は、YouTube に断られる（HTTP 429）ことがあるため、API を使います。

- AI には、タイトルと、説明欄を絞ったものを渡します。説明欄は、URL とハッシュタグを取り除き、リンクの見出しだけの行を捨て、先頭から `youtubeDescriptionMaxChars`（`Config.gs`。初期値 2,000 字）で切ります。タイトルを基準に、関係する内容だけを要約し、番組と無関係な宣伝・チャンネル紹介は無視するよう指示します。AI の判断なので、宣伝が混ざることはあります。
- **説明欄は、スレッドの原文にも保存する原文にも入れません**（宣伝やリンクが混ざるため）。本文を貼り付けたときは、貼り付けた本文を優先します（説明欄は AI に渡しません）。
- チャンネル名は「発信者／出演者」の候補になります。
- 動画の中身（話した内容・字幕）は読めません。AI が見るのは、投稿者が書いたタイトルと説明欄だけです。
- キー未設定・API の失敗・非公開の動画のときは、従来どおり、ページを取りに行き、取れなければ本文の貼り付けを促します。

YouTube のキーの作り方（無料の範囲）:

1. [Google Cloud コンソール](https://console.cloud.google.com/)でプロジェクトを作る（または既存のものを選ぶ）。
2. 「APIとサービス」→「ライブラリ」で「YouTube Data API v3」を有効にする。
3. 「APIとサービス」→「認証情報」→「認証情報を作成」→「API キー」でキーを作る。
4. キーを `YOUTUBE_API_KEY` に貼る。キーはコードやリポジトリには書かない。

動画1本の日付を調べる呼び出しは、1日あたりの上限（初期値 10,000 単位）のうち 1 単位です。上限に達した・動画が非公開・キーが無効のときは、発信日を空にして警告を出すだけで、ほかの機能は止まりません。支払い方法の入力を求められたら、そこで止めて確認してください（無料の範囲を超える設定はしません）。

「記録の一覧」の日付の列は「発信日」です（スマホは行の2行目に「発信 10/3」）。読む人に見せたいのは元の投稿・動画が出た日なので、登録日は表に出さず、行を開いた詳細にだけ出します。発信日が空の記録は「—」です（以前の記録は空のままです）。「並び順」と列の見出しの「発信日」で、発信日の新しい順に並べ替えられます（空の記録は最後）。初期の並びは、これまでどおり登録日の新しい順です。

### YouTube の発信日が入らないとき

「文章を整える」の結果画面の警告に、「YouTube の発信日を取得できませんでした（HTTP 403: …）」のように出ます。`:` のあとの名前が原因の手がかりです（`accessNotConfigured` = YouTube Data API v3 を、キーを作ったプロジェクトで有効にしていない、`keyInvalid` = キーが違う・有効になるまで最大5分、`quotaExceeded` = 1日の上限）。警告が出ず空のときは、`YOUTUBE_API_KEY` が未設定です。

原因を調べるには、GAS エディタで関数 `testYoutube` を選んで実行し、「実行ログ」の HTTP の番号と応答を見てください（API キーはログに出ません）。

### GAS を更新したとき

1. `gas/` の変更したファイルを、GAS エディタに貼り付けて保存する。
2. 「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →「バージョン: 新バージョン」→「デプロイ」。URL は変わりません。
3. 新しい権限が必要な変更なら、`authorizeOnce` をもう一度実行する。

### Gemini が使えないときの予備（Claude）

Gemini が混み合っている（HTTP 500・503・504）・利用回数の上限に達した（429）ときは、「文章を整える」「要約」が止まります。`ANTHROPIC_API_KEY` を入れておくと、Gemini を3秒待って1回やり直してもだめだったときだけ、Claude Haiku（`claude-haiku-5-5`）で同じ処理をやり直します。Gemini が正常なときは、Claude は呼びません。

- **費用:** 無料枠はありません。Haiku 5.5 の料金は、100万トークンあたり入力 $0.10・出力 $0.50（入力10万トークンまでの料金。2026年10月時点）で、「文章を整える」1回は約 0.2 円の目安です（考える深さを「中」にした分を含む。深さは `Config.gs` の `limits.claudeEffort`（low / medium / high）で変えられます。上げるほど精度は上がり、費用と時間が増えます）。Anthropic の Console で、支払い方法（クレジットの購入など）の設定が要ります。支払い情報の入力は、ご自身で行ってください。
- **切り替わったとき:** 結果画面の警告に「Claude（…）で整えました」と出ます。「利用量」シートのモデル名の欄に Claude のモデル名が入り、設定画面の「今月の概算」にも、Claude の料金で足されます（トークン数の列は、Gemini・Claude のどちらも同じ列に入ります）。
- **切り替えないとき:** `ANTHROPIC_API_KEY` が未設定／チラシ画像が HEIC・HEIF 形式（Claude は読めません。JPEG・PNG・WebP・GIF は読めます）。このときは、これまでと同じ日本語のエラーです。Claude も失敗したときは、Gemini のエラーに「Claude への切り替えも失敗しました（HTTP …）」が添わります。
- **キーの作り方:** [Anthropic Console](https://console.anthropic.com/)で API キーを作り、`ANTHROPIC_API_KEY` に貼ります（キーはコードやリポジトリには書きません）。
- **確かめ方:** GAS エディタで関数 `testClaude` を選んで実行し、「実行ログ」を見ます。短い要約と、「文章を整える」と同じ形式（構造化出力）の2回を試します（キーはログに出ません）。`HTTP 200` と、「読み取れた要約」「読み取れた結果」が出れば使えます。`HTTP 401: authentication_error` はキーが違う、`HTTP 400` の `invalid_request_error` は、支払い設定やモデル名を確かめてください。
- 判定の癖は Gemini と少し違うので、種別・カテゴリ・場所などが変わることがあります。曜日・URL の検査・テレビの補正・発信日などの、コード側の検査は、Claude の結果にもそのまま効きます。

### Jev の分類がうまくいかないとき

結果画面に「Jev による分類に失敗したため、Gemini の判定を使いました」と出る場合は、Gemini の判定で続けられます。原因を調べるには、GAS エディタで関数 `testJev` を選んで実行し、「実行ログ」の HTTP の番号と応答を確認してください（API キーはログに出ません）。

| 実行ログ | 意味と対処 |
|---|---|
| `HTTP 200` と「判定結果: {"kind":…}」 | 正常です |
| `HTTP 401`（authentication_error） | キーが無いか、無効です。[TypeSafe の管理画面](https://console.typesafe.ai/keys)に表示されたキーを、`apikey-` から最後まで**全体**を `TYPESAFE_API_KEY` に貼り直してください（頭の `apikey-` もキーの一部です） |
| `HTTP 403`（authentication_error） | キーは届いているが使えない状態です。管理画面で新しいキーを作り直して貼り直してください（作り直して解決した例があります） |
| `HTTP 422` | リクエストの形式の問題です。カテゴリ名・タグ名に極端に長いものがないか確認してください |
| `HTTP 429` `HTTP 529` | 混雑・回数の上限です。少し待ってから試してください |

## 記録の一覧ページ（記録を誰でも読めるようにする）

記録した投稿を、オープンチャットの人などが合言葉なしで読めるページです（`https://（アプリのURL）/archive.html`）。オープンチャットには、このページの URL を1つ貼っておけば、トークを遡らなくても記録を探せます。

- **見え方:** パソコンでは1件1行の一覧表、スマホでは1件2行に詰めて並びます（2行目の先頭に、入力元の X・Slack などを枠つきの文字で出します）。行を押すと、その下にトーク本文・リンク・「原文を読む」が開きます。
- **探し方:** 検索窓（タイトル・本文・原文・発信者・場所など）、カテゴリ（1つ選ぶ。件数つき）、タグ（「タグで絞り込む」を開いて複数選ぶ。初期値は「どれか1つでも持つ」で、「すべて持つ」に切り替えられる）、「開催予定のみ」。これらはすべて重ねて効きます。今の条件と件数が表示され、「条件をすべて解除」で戻せます。並べ替えは列の見出し（スマホは「並び順」）。最初は100件まで表示し、「さらに表示」で続きを出します。
- **表:** 種別の列は出しません（詳細の最初の行には出ます）。カテゴリ・タグの選択肢は、記録から自動で作ります。
- **スプレッドシートへのリンク:** 公開用スプレッドシート（`PUBLIC_SPREADSHEET_ID`）を設定していると、見出しの下に「スプレッドシートで表として見る」が出ます。未設定なら出ません。
- **配信・会議のリンク:** 記録の「配信・会議の URL」（保存先シートの見出しは「参加URL」のまま）は、リンク先に合わせた名前で出ます。YouTube は「YouTube で見る」、Zoom・Meet・Teams などは「オンライン会議に参加する」、それ以外は「配信・会議のページを開く」です。開催が終わっても隠しません。同じ会議室を繰り返し使っていて公開したくないときは、その記録の URL 欄を空にします。
- **トーク本文の結び:** 一覧に出すトーク本文からは、「詳細はスレッドにて ➡️」を取り除きます（原文は書き換えません。「全文はこちら ⬇️」と URL は残ります）。
- **出る項目:** 登録日・発信日・種別・発信者・ソース・カテゴリ・タイトル・概略・タグ・開催日時・場所・申込締切・出演者・トーク本文・原文・元の投稿の URL・参加 URL・申込 URL・コメント（スレッドに添えたもの）。**ID は出ません。**
- **ほかから開く:** `archive.html?q=タイトル&at=登録日時` の形で開くと、その投稿を開いた状態で表示します（公開用スプレッドシートのタイトルのリンクがこの形です）。
- **スプレッドシートは非公開のままで大丈夫です。** ページは GAS の読み取り専用の入口から、公開してよい項目だけを読みます。保存や編集はできません。
- **費用:** かかりません（AI を使わず、シートを読むだけです）。

**公開する手順**
1. GAS のスクリプトプロパティに `ARCHIVE_PUBLIC` = `true` を追加する（デプロイの更新は不要）。
2. リポジトリの `archive-config.js` の `gasUrl` に、GAS の Web アプリ URL（`https://script.google.com/macros/s/…/exec`）を入れて、main に反映する（Vercel が公開し直します）。この URL は秘密ではありません（合言葉が必要な操作は、URL だけではできません）。
3. `https://（アプリのURL）/archive.html` を開いて確かめ、オープンチャットに URL を貼る。

**読むだけの人へ伝える URL:** `https://（アプリのURL）/archive.html` だけです（ログイン不要。入力アプリを通らずに開けます）。

**公開をやめるとき:** `ARCHIVE_PUBLIC` を消すか `false` にすると、すぐにページに何も出なくなります。

## 公開用スプレッドシート（記録をスプレッドシートでも一覧できるようにする）

登録用のスプレッドシート（非公開）とは別に、公開用のスプレッドシートを作り、その「記録一覧」タブに記録を自動で書き写します。オープンチャットの人は、スプレッドシートの一覧でさっと見て、詳しく知りたい投稿はタイトルを押して記録の一覧ページで読めます。

```
登録用スプレッドシート（非公開のまま）
   │ 保存・更新・削除のたびに、GAS が「記録一覧」タブを丸ごと書き直す
   ▼
公開用スプレッドシート（リンクを知っている全員・閲覧者）
 ├ 「記録一覧」タブ … アプリが自動で作る一覧（手で書き換えない）
 └ ご自身で足すタブ … トップページ・ルールなど、自由に使える（アプリは触らない）
```

- **載る列:** 登録日時・発信日・カテゴリ・発信者／出演者・ソース・タイトル・概略・開催日時・場所・出演者・申込締切・参加URL・申込URL・元の投稿のURL・タグ・スレッド詳細（原文）・コメント・種別（カテゴリと取り違えられないよう末尾。見せたくなければ列を非表示にするか、`publicSheet.columns` から外す）。**ID とトーク本文は載せません**（トーク本文はほかの列とほぼ重なるので、記録の一覧ページで読めます）。列と並びは `gas/Config.gs` の `publicSheet.columns` で変えられます。
- **タイトル:** 押すと、記録の一覧ページでその投稿を開いた状態になります。
- **見え方:** 新しい順、見出しの行は固定。長い文は折り返さずセルの幅で切るので、行の高さがそろいます（セルを選ぶと全文が読めます）。
- **書き写しに失敗したとき:** 保存自体は成功し、画面に警告が出ます。アプリの設定画面の「公開用シートを作り直す」で、いつでも登録用の内容から作り直せます。
- **費用:** かかりません。

**作る手順（1回だけ）**
1. GAS エディタに、最新の `Code.gs`・`Config.gs`・`appsscript.json` を貼り付けて保存する（別のスプレッドシートを書き換えるため、権限が広がっています）。
2. `Config.gs` の `publicSheet.archiveUrl` が、自分のアプリの記録の一覧ページの URL になっているか確かめる。
3. エディタで関数 `createPublicSpreadsheet` を選んで「実行」し、表示される権限を承認する。公開用のスプレッドシートが作られ、実行ログに URL が出ます（スクリプトプロパティ `PUBLIC_SPREADSHEET_ID` にも自動で入ります）。
4. 「デプロイを管理」→ 新バージョンでデプロイする。
5. 作られたスプレッドシートを開き、共有を「リンクを知っている全員」・「閲覧者」にする。
6. アプリの設定画面に「公開用スプレッドシートを開く」のリンクが出ることを確かめる。

## 料金の上限と予算アラート（必ず設定してください）

API の使いすぎや、合言葉の漏えいによる不正利用に備えて、上限を設定します。

### Gemini API

1. [Google AI Studio](https://aistudio.google.com/) の「Spend」（支出）ページを開く。
2. 「Monthly spend cap」（月額の支出上限）の「Edit spend cap」で、プロジェクトの月額上限を設定する。
3. 加えて、Google Cloud コンソールの「お支払い」→「予算とアラート」で予算を作り、50%・90%・100% でメールが届くようにする。

> **データの扱い:** 無料枠では、送った内容（プロンプトと応答）が Google の製品改善に使われることがあります。有料枠では使われません。非公開の情報を扱う場合は、有料枠（課金を有効にしたプロジェクト）のキーを使ってください。

### Jev（TypeSafe）を使う場合

TypeSafe のダッシュボードで、利用量と上限の設定を確認してください（入力トークン数で課金されます）。

### 合言葉が漏れたとき

- **管理者の合言葉（`SHARED_TOKEN`）が漏れたとき**
  1. スクリプトプロパティの `SHARED_TOKEN` を新しい値に変える（デプロイの更新は不要）。
  2. 管理者の端末の設定画面の合言葉を変える。
  3. 不審な利用があれば、Gemini の API キーも作り直す。
- **入力する人の端末を失くした・その人の合言葉が漏れたとき**: 設定画面の「入力する人（利用者）」で、その人を「止める」か「削除」する（ほかの人はそのまま使える）。続けて使う人なら、削除してから新しい招待リンクを渡し、名前を登録し直してもらう。
- **まだ使われていない招待リンクが漏れたとき**: 「まだ使われていない招待」から取り消す。

### 使い方のページ

アプリの上のアプリ名の右にある「使い方」（`/help.html`）に、入力する人向けの使い方をまとめています（最初の登録、スマホと PC での投稿文の作り方、結果の画面、一覧・検索、困ったとき）。合言葉なしで読めます。画面の文言や手順を変えたときは、このページも直してください。

### 複数の人で入力する（招待リンク）

管理者（`SHARED_TOKEN` を知っている人）だけが、設定画面の「入力する人（利用者）」で招待リンクを作れます。

1. 「招待リンクを作る」を押すと、**招待リンクが1回だけ**表示されます（画面を閉じる・読み込み直すと、もう表示できません）。名前は入れません。
2. 招待リンクを、入力してもらう人に渡します。リンクを開くと「名前を登録して始める」が出るので、その人が自分の名前を入れて「登録する」を押します。その人用の合言葉が作られ、その端末に自動で保存されます。アドレス欄からは、リンクの「#invite=…」の部分がすぐ消えます。入力する人の設定画面には、合言葉は表示されません。
   - **招待リンクは、同じ人の端末として2台まで使えます。** 1台目で名前を登録したあと、同じリンクを2台目（スマホとパソコンなど）で開き、**1台目と同じ名前**を入れると、同じ人の合言葉がもう1つ作られます（自分が保存した記録を、どちらの端末からも編集できます）。2台使うと、リンクは使えなくなります。3台目以降は、新しいリンクを作ってください。
   - **注意**: 1台目の登録のあと、2台目の登録が済むまでは、リンクを知っている人なら誰でも（名前さえ合わせれば）2台目として入れます。複数の人がいるチャットには送らず、本人だけに渡してください（利用者が了承。2026-11-03）。万一のときは、一覧でその人を「止める」・「削除」するか、「まだ使われていない招待」から取り消します。
   - 使い切らないまま **7日** たつと、リンクは使えなくなります。「まだ使われていない招待」に、作った日時と期限、1台目が登録済みか（あと何台か）が出ます。不要になったら取り消せます。
   - 名前は30文字まで、ほかの人と同じ名前は使えません。名前を間違えて断られたときは、直して同じリンクでやり直せます。
   - 渡し方の例: 「リンクを開いて名前を登録してください。そのあと、ブラウザのメニューから『ホーム画面に追加』（PC はアドレス欄のインストールのアイコン）を選ぶと、アプリとして使えます。」
3. 入力する人にできること: 入力・保存・検索。編集・削除は**自分が保存した記録だけ**です（ほかの記録は、開いてコピーすることはできます）。設定の変更（カテゴリ・タグ・種別・発信者の候補）、公開用シートの作り直し、AI の使用量の表示、保存先スプレッドシートへのリンク、利用者の管理は、管理者だけです。
4. 管理者は、すべての記録を編集・削除できます。記録を開くと、保存した人の名前が出ます（管理者が保存した記録・この機能の前の記録は、保存した人なし）。

仕組みと注意:

- GAS には、入力する人の合言葉と招待リンクの印のどちらも、そのものは保存せず、元に戻せない形（SHA-256）にした値だけを `USERS_JSON`・`INVITES_JSON`（スクリプトプロパティ）に持ちます。スプレッドシートを見られても、合言葉は分かりません。
- 招待リンクの印は、「#」より後ろに入れます。ブラウザはこの部分をサーバー（Vercel など）に送らないので、アクセスの記録には残りません。リンクを送ったチャットの履歴には残りますが、2台使い切ったリンク・7日たったリンクは使えません。
- 名前の登録（`claimInvite`）だけは、合言葉なしで GAS を呼べます（まだ合言葉を持っていないため）。推測できない64桁の招待の印が無いと通らず、返すのはその人の合言葉と名前だけです。
- 合言葉は、使う人の端末に保存されます（共通の合言葉と同じで、開発者ツールを使えば取り出せます）。そのため、人ごとに別の合言葉にして、漏れた人だけを止められるようにしています。
- 保存先のシートに「保存者ID」の列が足されます（誰の記録かを覚える列です。消したり書き換えたりしないでください。公開用シートと記録の一覧には出ません）。
- AI の利用回数の上限は付けていません（入力する人が増えると、AI の料金が増えます。設定画面の「今月の概算」で確かめられます）。人数の上限は30人です。

## リポジトリを公開する前に（秘密情報のスキャン）

最初は非公開リポジトリで運用しています。公開する（または公開リポジトリにフォークする）前に、**履歴を含めて**秘密情報が入っていないかを確かめてください。

1. [gitleaks](https://github.com/gitleaks/gitleaks) で、全コミットの履歴をスキャンする（Docker を使う例）。

   ```bash
   docker run --rm -v "${PWD}:/repo" zricethezav/gitleaks:latest git /repo -v
   ```

2. 念のため、API キーらしき文字列を履歴から検索する（Gemini の API キーは `AIza` で始まる）。

   ```bash
   git log -p --all | grep -nE "AIza[0-9A-Za-z_-]{30,}|Bearer [0-9A-Za-z._-]{20,}|SHARED_TOKEN *[:=] *['\"][^'\"]+"
   ```

3. 見つかった場合は、**そのキーを無効化して作り直す**（履歴から消すだけでは不十分です。すでに複製された可能性があるため）。そのうえで、履歴の書き換え（`git filter-repo` など）を検討する。
4. スプレッドシートの共有範囲（「リンクを知っている全員」になっていないか）も確認する。

### スプレッドシートの共有について

アプリの設定画面に「保存先のスプレッドシートを開く」リンクがあります（合言葉が一致したときだけ表示）。開けるかどうかは、シートの共有設定で決まります。

- **おすすめ:** 共有は「制限付き」にし、見せたい人の Google アカウントを1人ずつ追加する。リンクの URL が広がっても、追加した人以外は開けません。
- **「リンクを知っている全員」にした場合:** URL を知っている人は、Google にログインしていなくても誰でも閲覧できます。シートには Slack からの転載の原文やメモも入るので、注意してください。
- アプリの保存・一覧は、シートの共有設定に関係なく動きます（GAS がシートの持ち主の権限で読み書きするため）。

## 設計メモ

- **原文は AI を通さない:** スレッドの本文は、共有・入力・取得した原文をそのまま使います。分割しても、各通をつなぐと原文に戻ります（テストで確認しています）。
- **日付:** 保存は ISO の絶対日付です。曜日・「本日」「明日」は表示・コピーのたびに計算します。チラシに書かれた曜日と計算した曜日が違えば警告します。
- **セルへの書き込み:** 空でない値はすべて先頭にアポストロフィを付けて文字列として書きます（数式インジェクション対策と、日付・数値への自動変換の防止）。
- **列は見出しの名前で読み書きします:** アプリは1行目の見出し（「発信者」「タイトル」など）を見て、どの列に何があるかを毎回判断します。
  - スプレッドシート上で列を自由に並べ替えられます（列番号の部分をドラッグ）。新しく作るシートは「登録日時／種別／発信者／ソース／…」の並びです。
  - 自分で足した列（「投稿済み」など）は、どの位置にあってもアプリは触りません。編集で保存し直すときも、アプリの列だけを書き換えます。
  - 見出しが見つからない列（古いシートなど）は、右端に自動で足します（それまでの行は空欄）。
  - **見出しの文字は変えないでください。** 書き換えると、アプリは別の列とみなして右端に新しい列を作ります。同じ見出しが2つあると、左側の列を使います。

## アクセシビリティ

JIS X 8341-3:2016 の適合レベル AA、WCAG 2.1／2.2 の A・AA を前提にしています。

- 状態メッセージ（整えています・整えました・コピーしました・警告）は `aria-live` で読み上げます。
- フォーカスは太い輪郭線で表示し、固定表示の帯にフォーカスが隠れないようにしています。
- 文字のコントラストは 4.5:1 以上、ボタン・入力欄は高さ 44px 以上です。
- 幅 320px でも横スクロールなしで使えます。
- 自動の検査ツール（axe-core）で、アプリの各画面と記録の一覧ページに WCAG 2.1／2.2 の A・AA の違反が無いことを確かめています（2026-10-05）。自動検査では見つからない問題もあるので、読み上げ（TalkBack）での確認手順を [docs/verification-checklist.md](docs/verification-checklist.md) に残しています。
