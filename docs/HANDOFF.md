## 2. 何のアプリか

Slack・X・Instagram・Threads・LINE公式・note・議員の告知・チラシ画像などの告知を、LINE オープンチャットにそのまま貼れる文章に整える PWA です。

- **① トーク本体**: AI の提案（タイトル・箇条書きの概略・日時など）から組み立てる。画面で手直しできる。
- **② スレッド**: 前置き＋**原文そのまま**（AI を通さない）。長文は分割する。
- **③ 記録**: Google スプレッドシートに保存し、一覧から探せる。

記録の一覧ページ（`archive.html`）と、公開用スプレッドシート（「記録一覧」タブ）にも自動で反映されます。

## 5. 決まっている仕様と、その理由（蒸し返さない）

- **曜日は LLM に任せない**（コードで計算）。「本日」「明日」はコピーした時点で付ける。
- **スレッドの原文は一字も変えない**。例外は、利用者がボタンを押したときだけ（要約・絵文字の名前の除去）。分割しても、つなぐと原文に戻る。
- 日付が未確定（「または」「未定」など）なら、日時を空にして警告する。AI の `dateUncertain` と、原文からの機械的な検出の両方で判定する。
- 参加 URL・申込 URL は、**原文に実際にある URL だけ**を残す（`findUrlInText_`）。`https://` なしの書き方（`meet.google.com/…`）も拾い、`https://` を補う。
- URL は外部の短縮サービスを使わない。追跡用のパラメーターを取り除くだけ（`cleanUrl_`）。
- トーク本体の書式: タイトルを【】で囲む、概略は体言止めの箇条書き、スケジュールは「いつ・どこで」、場所は「対面（高崎）＆オンライン」の形、最後に「詳細はスレッドにて ➡️」。スレッドを使わないときは「全文はこちら ⬇️」と URL。
- スレッドの前置きは、**全文（初期値）／抜粋の選択で書き分ける**。発信者の有無では切り替えない（名前があれば「発信者は○○です。」を足すだけ）。「（全文）」とは書かない。抜粋を選んでも、アプリは文を削らない。
- 絵文字の名前（`:○○:`）の除去: ボタンを押したときだけ。行の最後で消したら、句読点・閉じかっこがなければ「。」を付ける。時刻（`21:20`）・URL・ふつうのコロンは消さない。末尾の「（編集済み）」も消す。
- 種別（お知らせ／スケジュールなど、トークの形を決める）とカテゴリ（記録の分類）は別物のまま残す（利用者が判断済み）。
- 種別は、組み込みの3つ（`Config.gs` の `kinds`。消せない）に加え、設定画面から追加・削除できる（名前・説明・「日時あり」の選択。最大20個）。「日時あり」（`schedule`）の種別は、トークに日時・場所の行を出す。`schedule` キーの種別は、設定に印が届かなくても日時を出す（`Config.gs` が古いままでも壊れないため）。追加した種別を消すと、その種別の保存済みの記録は、開くと種別が未選択になる。
- タグ検索は、複数のタグを選んだとき、初期値は OR（どれか1つでも持つ）で、「すべて持つ」（AND）に切り替えられる（`tagMode`）。
- **参加 URL（オンライン会議・配信の URL）はトークに出さない**（利用者の希望）。欄・記録・公開一覧のリンク・スレッドの原文には残す。申込 URL は出す。
- 概略（記録の `summary`）には、「詳細はスレッドにて ➡️」「全文はこちら ⬇️」を入れない。AI の結果と保存前に取り除く（`stripThreadGuide_`）。この結びはトーク本体にだけ付く。
- 画面・文書での呼び名は「記録の一覧」（旧「公開の一覧（ページ）」）に統一。「公開用スプレッドシート」の呼び名は変えない。記録の一覧に出すトーク本文からは「詳細はスレッドにて ➡️」だけを取り除く（`toPublicItem_`。「全文はこちら ⬇️」と URL・原文は残す）。
- 記録の一覧ページ（`archive.html`）の絞り込み: 検索・カテゴリ（1つ選ぶ）・タグ（複数選択。初期値 OR、「すべて持つ」に切り替え。折りたたみ）・開催予定のみは、すべて重ねて効く。選択肢と件数（記録全体での数）は記録から自動で作る（`archiveFacets`）。今の条件と件数を表示し、「条件をすべて解除」で戻せる（並び順はそのまま）。見出しの下に公開用スプレッドシートへのリンク（GAS が `publicSpreadsheetUrl` を返す。未設定なら出ない）。
- 記録の一覧の「開催日の近い順」（開催日時の列の昇順）は、今日以降の開催を早い順に並べ、そのあとに過去の開催を新しい順に並べる。開催日の無い記録は最後。降順はその逆（`buildArchiveView`）。
- **発信日**（記録の `postedAt`、シートの見出し「発信日」、`YYYY-MM-DD`・日本時間）: 元の投稿・動画が出た日。「文章を整える」のとき URL から自動で入れ、結果画面の欄で直せる（空でも保存できる）。X・Instagram・Threads・Slack は URL の番号から計算（`postedDateFromUrl_`。外部通信なし）。YouTube は YouTube Data API（`videos.list`、1 単位。1日の初期上限 10,000 単位）で公開日を取る。キーはスクリプトプロパティ `YOUTUBE_API_KEY`（未設定なら呼ばず、警告も出さない）。失敗しても analyze は止めず、空にして警告だけ出す。note・LINE公式・チラシなどは自動では入らない（手で入れる）。入力元の一覧に YouTube は無いので、YouTube の URL は入力元「その他」のまま日付だけ拾う。以前の記録の発信日は空のまま（一括では埋めない。利用者が判断済み）。
- 元の URL が YouTube のときは、テレビの手がかり（`mentionsTv_`）を**タイトルだけ**で見る（説明欄は見ない）。AI が「番組への出演」からテレビ（`attendance: tv`）と誤判定しても、タイトルに手がかりが無ければ場所を「オンライン」にし、タイトルに手がかりがあればテレビにする。理由: YouTube の説明欄には、制作会社名（TBS など）・出演者の経歴（「TBSテレビ入社」）・ハッシュタグが入るだけで、テレビ放送とは限らない（2026-10-19、TBS CROSS DIG の YouTube 番組が、説明欄の「TBS」でテレビのままになった件）。YouTube 以外の URL は、従来どおり原文も見る。
- YouTube のページは GAS からの取得が HTTP 429 で断られることがある（本文は貼り付けが前提。利用者の実機で確認）。発信日の API（`videos.list`）は別の経路なので、ページが取れなくても使える。API の失敗は、警告に HTTP の番号と原因の名前（`accessNotConfigured` など）を入れる。原因の切り分けは GAS の `testYoutube`（実行ログ）。
- 記録の一覧の日付の列は「発信日」だけを出す（`archiveDateLabel`。今年でなければ年も出す。空なら PC は「—」、スマホは出さない）。**登録日は表に出さず、詳細にだけ出す**（読む人に見せたい日付は元の投稿・動画が出た日。登録日を出すと、実際の発信日と取り違えるという利用者の指摘による。2026-10-18）。スマホの2行目は「発信 10/3」（開催日と取り違えないよう「発信」を付ける）。並べ替えに「発信日の新しい順」（`posted`。列の見出しからも。空は昇順・降順どちらでも最後）を足し、月の区切りは並べ替えに使う日付の月（発信日では「発信日なし」）。初期の並びは登録日の新しい順のまま（以前の記録の発信日がまだ空のため）。公開用シートには「発信日」の列を登録日時の次に足した（`publicSheet.columns`）。**列の位置が1つずれるので、種別の列などを非表示にしている場合は確かめ直す。**
- 記録の一覧のスマホの行（2行目の先頭）には、入力元（`sourceLabel`。X・Slack など）を枠つきの文字で出す（何から来た記録か分かるように。パソコンの表には出さない）。
- 記録の一覧の表には種別の列を出さない（詳細の最初の行には出す。検索の対象からも外した。読む人にはトークの形は関係なく、カテゴリと取り違えやすいため）。タグは行には出さない。
- 配信・会議の URL（記録の `joinUrl`）のリンクは、リンク先で言葉を変える（`streamLinkInfo`。YouTube →「YouTube で見る」、Zoom・Meet・Teams など →「オンライン会議に参加する」、その他 →「配信・会議のページを開く」）。開催が終わっても隠さない（利用者が決定。同じ会議室を繰り返し使うなら、その記録の URL 欄を空にしてもらう）。入力アプリの欄の表示名は「配信・会議の URL」。
- 表示名は「発信者／出演者」（入力アプリ・記録の一覧ページ・公開用シート）。**保存先シートの見出しは「発信者」のまま**（列を見出しの名前で探すので、変えると既存のシートを読めなくなる）。スケジュール型の「出演者」（トークの 🎤 の行）は別の欄。
- 開催形式（AI が返す `attendance`）に `tv` がある。テレビ番組への出演・放送は、場所の表記を「テレビ」にする（YouTube やオンライン会議の配信は「オンライン」のまま）。表記は `Config.gs` の `placeLabels.tv`。AI が「オンライン」「不明」と返しても、タイトル・原文にテレビ局・番組の手がかり（「テレビ」「地上波」「TBS」「BS-朝日」など。`mentionsTv_`）があれば、コード側で「テレビ」にする（AI の判定だけに頼らない。対面と返したものは変えない）。
- 公開用シートの並びは、カテゴリを先頭側に、種別を末尾に置く（カテゴリと取り違えられないため）。種別の列は、まだ非表示にしていない。後日非表示にするか、このまま表示するかは未定（利用者が決める）。列は `Config.gs` の `publicSheet.columns` で変えられる。非表示は列の位置に付くので、並びを変えたら非表示を確かめ直す。
- シートの列は見出しの名前で探す（列の並びに頼らない）。発信者は「種別」と「ソース」の間。旧「メモ」列は「コメント」として読む。
- 公開用スプレッドシートには、ID とコメント以外を載せる。トーク本文の列は載せない。タイトルは元の投稿へのリンク。
- Gemini が 500/503/504 なら、3秒待って1回だけやり直す。やり直しても 429・500・503・504 で、`ANTHROPIC_API_KEY` があれば、Claude Haiku（`claude-haiku-5-5`）で同じ処理（「文章を整える」「要約」）をやり直す（`callClaudeFallback_`。Claude の応答を Gemini の形に直して、あとの解析・使用量の記録をそのまま使う）。キー未設定・HEIC/HEIF の画像のときは切り替えない。Claude も失敗したら Gemini のエラーに「Claude への切り替えも失敗しました（HTTP …）」を添える。切り替えたら結果画面の警告に出し、使用量は Claude の料金（`Config.gs` の `claudeInputUsdPerMTok` など）で足す。Claude の API は無料枠なし（2026-10-20、利用者が了承）。**本物の Claude API での確認は、利用者が `testClaude`（GAS エディタ）で行う（AI 側ではキーが無く未確認）。**429 はやり直さない。どちらも日本語のエラーにする。

```

```
