# 実機での確認

自動テスト（`npm test`）と開発サーバーでは確かめられない項目の、確認の状況と手順です。
一人で全部を試すのは負担が大きいので、項目を次の4つに分けています（2026-10-05 時点）。

| 区分 | 意味 |
|---|---|
| ✅ 確認済み | 実機・本番で確かめた |
| ➖ 確認不要 | 今の設定のままで問題が出にくい。問題が出たときだけ、下の「必要になったときの手順」で確かめる |
| 👀 使いながら | ふだん使いながら、気になることがあれば記録・調整する |
| 🤖 自動検査 | 開発者が自動の検査ツールで確かめた（人の手での確認の完全な代わりではない） |

前提: GAS をデプロイし、PWA を Vercel に公開し、Android 端末でホーム画面に追加（インストール）済みであること。共有シートにアプリが出るのは、インストール後です。

## 必要になったときの手順

### Jev の入力の上限

公式ドキュメント上の上限は「1 回あたり 64k トークン、state と最も長い質問の合計で 32k トークン」です。文字数での上限は書かれていません。

1. `gas/Config.gs` の `limits.jevInputMaxChars` を一時的に上げる（16,000・24,000 など）。
2. その文字数の日本語の本文で「文章を整える」を押す。
3. 警告「Jev による分類に失敗したため…」が出るかを見る。出たら GAS エディタで `testJev` を実行し、HTTP の番号を確かめる。
4. 成功した最大値の 8 割程度を `limits.jevInputMaxChars` にする。

### LINE の1通あたりの文字数の上限

1. テスト用のオープンチャットのスレッドに、3,000・5,000・10,000 文字の文章を貼ってみる。
2. 送信できたか、途中で切れたかを見る。
3. 結果に合わせて `gas/Config.gs` の `limits.threadMessageMaxChars` を決める（絵文字は 1 文字を 2 文字と数えるので、安全側になる）。

### チラシ画像の読み取り精度

1. 読み間違えたチラシがあれば、日付・時刻・場所・締切のどれを、どう間違えたかを控える。
2. 間違いが続くようなら、プロンプト（`gas/Code.gs` の `buildGeminiAnalyzeRequest_`）を調整するか、モデル（スクリプトプロパティ `GEMINI_MODEL`）を変えて比べる。

### スプレッドシートへの書き込み

1. タイトルを `=1+1`、場所を `2026-10-03` にして保存する。
2. スプレッドシートで、セルに `=1+1` と `2026-10-03` が**文字のまま**表示されること（計算されたり日付に変わったりしない）を見る。
3. アプリの一覧で開いたとき、先頭にアポストロフィ（'）が付いていないことを見る。

### 記録の一覧ページ

1. Google にログインしていないブラウザ（シークレットウィンドウ）で `/archive.html` を開き、一覧が出ることを確かめる。
2. 行を押して、トーク本文・リンク・原文が読めること、メモが出ていないことを確かめる。トーク本文の最後に「詳細はスレッドにて ➡️」が出ていないこと（GAS の貼り替え後）も確かめる。
3. 件数が増えて読み込みが遅く感じたら（目安: 10 秒以上）、分けて読み込む形への改善を検討する。
4. `ARCHIVE_PUBLIC` を消すと、ページに何も出なくなることを確かめる（すぐ戻す）。

### スクリーンリーダー（TalkBack）

1. TalkBack をオンにして、入力 → 文章を整える → コピー → 保存 の流れを操作する。
2. 「文章を整えています」「文章を整えました」「〇通目をコピーしました」「保存しました」が読み上げられることを確かめる。
3. 警告（曜日の食い違い・重複）が読み上げられる、または見出しから辿れることを確かめる。

### アクセシビリティの自動検査（開発者向け）

開発サーバー（`npm run dev`）で各画面を開き、ブラウザの開発者ツールのコンソールで axe-core を読み込んで実行する。

```js
await new Promise((ok) => { const s = document.createElement('script'); s.src = 'https://cdnjs.cloudflare.com/ajax/libs/axe-core/4.10.2/axe.min.js'; s.onload = ok; document.head.appendChild(s); });
(await axe.run(document, { runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa'] } })).violations;
```

「要確認（incomplete）」の色のコントラストは、固定表示の帯や画面の端に重なって判定できなかったものが多い。文字色と背景色を計算して確かめる。
