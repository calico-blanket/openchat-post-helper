# 実機での確認手順

自動テスト（`npm test`）と開発サーバーでは確かめられない項目です。結果は各項目の「結果」欄に書き込み、設定値の変更が必要なら `gas/Config.gs` を直します。

前提: GAS をデプロイし、PWA を Vercel に公開し、Android 端末でホーム画面に追加（インストール）済みであること。共有シートにアプリが出るのは、インストール後です。

---

## ① X から共有したとき本文が入るか

1. X アプリで、文字だけの短い投稿を開き「共有」→「投稿ヘルパー」を選ぶ。
2. 結果画面の「原文」欄に投稿の本文が入っているかを見る。
3. 長い投稿（280 文字を超えるもの）でも同じことをする。
4. 原文の末尾が「…」で切れていないか、「途中で切れている可能性」の警告が出るかを見る。

| 投稿 | 共有で届いた内容（URL のみ／本文あり） | 原文に全文が入ったか | 結果 |
|---|---|---|---|
| 短い投稿 | | | |
| 長い投稿 | URL（PC では URL を入力） | 入らない。約250字で「…」＋画像リンクで切れる（無料で全文を取れる経路は無い） | 2026-10-04 確認。X で「さらに表示」を開いて全文をコピーし、本文欄に貼って対応する |

- 途中で切れる場合: 本文を貼り付けて「文章を整える」を押し直す運用にする（アプリは貼り付けた本文が長ければそちらを使う）。

## ② Slack と LINE 公式から共有したとき本文が入るか

1. Slack アプリでメッセージの「共有」→「投稿ヘルパー」を選ぶ（メッセージのメニューに「共有」が無い場合は「リンクをコピー」しか使えない）。
2. LINE 公式アカウントのメッセージ・投稿を長押し →「共有」→「投稿ヘルパー」を選ぶ。
3. 入力画面の「本文」欄に何が入るかを記録する。

| 共有元 | 共有で届いた内容 | 本文が入ったか | 結果 |
|---|---|---|---|
| Slack | 共有できない（他のアプリに転送できず、共有・転送の URL も無い） | ― | 2026-10-04 確認。本文をコピーして本文欄に貼って対応する |
| LINE 公式（トーク） | スマホ: 共有メニューからアプリに本文が届く／PC: 共有・転送の URL が無い | スマホは入る | 2026-10-04 確認。スマホは共有、PC は本文を貼り付けて対応する |
| LINE 公式（VOOM・投稿） | | | |

- 本文が入らない場合は「本文をコピー → アプリの本文欄に貼り付け」の手順を README に追記する。

## ③ Jev の入力長の上限

公式ドキュメント上の上限は「1 回あたり 64k トークン、state と最も長い質問の合計で 32k トークン」です。文字数での上限は書かれていないため、実際に確かめます。

1. スクリプトプロパティに `TYPESAFE_API_KEY` を設定する。
2. 8,000 文字・16,000 文字・24,000 文字の日本語の本文で「文章を整える」を押す。
   （`gas/Config.gs` の `limits.jevInputMaxChars` を一時的に上げて試す）
3. 警告「Jev による分類に失敗しました」が出るか、出たらその HTTP コードと内容を記録する。

| 文字数 | 結果 |
|---|---|
| 8,000 | |
| 16,000 | |
| 24,000 | |

- 結果に合わせて `limits.jevInputMaxChars` を決める（余裕を見て、成功した最大値の 8 割程度）。

## ④ LINE の1通あたりの文字数上限

1. スレッドに、1,000 文字・3,000 文字・5,000 文字・10,000 文字の文章を貼ってみる（テスト用のオープンチャットで行う）。
2. 送信できたか、途中で切れたかを記録する。

| 文字数 | 結果 |
|---|---|
| 1,000 | |
| 3,000 | |
| 5,000 | |
| 10,000 | |

- 結果に合わせて `limits.threadMessageMaxChars` を決める。初期値は 1,000 文字（読みやすさも考えた控えめな値）。
- 絵文字は 1 文字を 2 文字と数えている（アプリ側は安全側に数える）。

## ⑤ チラシ画像からの日時の読み取り精度

1. 実際のチラシの写真を 10 枚ほど用意する（曜日入り・曜日なし、縦書き、和暦、手書き風など）。
2. 「画像を選ぶ」→「文章を整える」を押し、結果画面の開催日・開始時刻・場所・申込締切を、チラシと見比べる。
3. 曜日の食い違い警告が正しく出るか（チラシの曜日と日付が合わないものを1枚含める）も見る。

| 画像 | 日付 | 時刻 | 場所 | 締切 | 曜日の警告 | メモ |
|---|---|---|---|---|---|---|
| 1 | | | | | | |
| 2 | | | | | | |

- 間違いが多い項目は、プロンプト（`gas/Code.gs` の `buildGeminiAnalyzeRequest_`）を調整するか、モデル（スクリプトプロパティ `GEMINI_MODEL`）を変えて比べる。

## そのほかの確認

### スプレッドシートへの書き込み

1. タイトルを `=1+1`、場所を `2026-10-03` にして保存する。
2. スプレッドシートで、セルに `=1+1` と `2026-10-03` が**文字のまま**表示されること（計算されたり日付に変わったりしない）を見る。
3. アプリの一覧で開いたとき、先頭にアポストロフィ（'）が付いていないことを見る。

### 所要時間（共有から結果表示まで）

1. 共有から開いて結果が出るまでの時間は、設定画面の「所要時間の記録」に自動で残る。
2. 入力元ごとに 3 回ずつ記録し、README の「所要時間の実測」の表に書き写す。

### 公開の一覧ページ

1. `ARCHIVE_PUBLIC` を `true` にし、`archive-config.js` に GAS の URL を入れて公開する。
2. Google にログインしていないブラウザ（シークレットウィンドウ）で `/archive.html` を開き、一覧が出ることを確かめる。
3. 行を押して、トーク本文・リンク・原文が読めること、メモが出ていないことを確かめる。
4. 件数が多いときの読み込み時間を測る（数百件で数秒以内が目安）。遅ければ README の「公開の一覧ページ」の改善（分割読み込み）を検討する。
5. `ARCHIVE_PUBLIC` を消して、ページに何も出なくなることを確かめる（すぐ戻す）。

### スクリーンリーダー（TalkBack）

1. TalkBack をオンにして、入力 → 文章を整える → コピー → 保存 の流れを操作する。
2. 「文章を整えています」「文章を整えました」「〇通目をコピーしました」「保存しました」が読み上げられることを確かめる。
3. 警告（曜日の食い違い・重複）が読み上げられる、または見出しから辿れることを確かめる。
